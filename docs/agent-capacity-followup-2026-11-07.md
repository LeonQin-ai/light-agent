# Agent 并发容量复测

2026-11-07，测试使用固定版本的 Cognitive OS 运行时和内置 Mock LLM。文件负载通过真实文件工具写入唯一标记，并校验文件内容。

## Linux

OpenCloudOS 虚拟机有 4 vCPU 和 3655 MiB RAM。每个 Agent 使用独立的 Docker/runc 容器、状态目录和工作区。每实例配置 8 个调度线程，负载目标为每秒 2 个任务。短测和长测都要求零错误、零 OOM、至少完成计划任务的 95%，以及 P95 不超过 1 秒。

| 负载 | 实例数 | 时间 | 完成任务 | 错误 | P95 | 结果 |
|---|---:|---:|---:|---:|---:|---|
| 轻量 Mock 推理，上轮确认 | 128 | 60.3 秒 | 15,360 | 0 | 181 ms | 通过 |
| 轻量 Mock 推理，本轮短测 | 136 | 12.2 秒 | 3,264 | 0 | 256 ms | 通过 |
| 轻量 Mock 推理，本轮长测 | 136 | 56.4 秒 | 15,368 | 0 | 164 ms | 内存余量触发中止 |
| 文件工具 | 72 | 120.5 秒 | 17,113 | 0 | 315 ms | 通过 |
| 文件工具 | 80 | 120.5 秒 | 18,052 | 1 | 711 ms | 未达标 |
| 文件工具 | 88 | 120.6 秒 | 18,229 | 13 | 985 ms | 未达标 |
| 文件工具，逐级扩容后 | 96 | 48.3 秒 | 8,333 | 2 | 832 ms | 超时并触发内存保护 |

72 个文件工具实例的吞吐量约为 142 任务/秒，CPU 平均占用约 69.6%，主机可用内存最低约 769 MiB。73 至 79 个实例的长测尚未测量。轻量负载本轮达到 142 个启动就绪实例，上轮达到 154 个。扩容需要预留 600 MiB 加一个容器的 128 MiB 上限，持续负载低于 600 MiB 时停止。各轮测试结束后 Docker 容器已清理。

100 万个独立运行时超出这台 VM 的资源范围。按本轮 128 个实例进入负载前的 cgroup 平均用量约 2 MiB 计算，仅 Agent 容器就约需 1.9 TiB 内存，Docker、系统开销和负载增长另计。本机内核 `threads-max` 实测为 28,936，连每实例只计一个 Linux 任务也无法达到 100 万。休眠身份的存储量属于另一项容量指标。

## Windows

Windows 11 家庭中文版，Intel Core i5-8265U，8 个逻辑处理器和约 7.85 GiB 物理内存。固件虚拟化可用，`WHvGetCapability` 返回成功且 `HypervisorPresent=0`。Cloud Hypervisor 的 MSHV 后端要求 Linux 根分区的 `/dev/mshv`，所以本轮采用 QEMU 11.1.0 的 TCG 软件模拟完成独立来宾测试。[Cloud Hypervisor MSHV 文档](https://github.com/cloud-hypervisor/cloud-hypervisor/blob/main/docs/mshv.md) · [QEMU Windows 构建](https://qemu.weilnetz.de/w64/)

每个 Linux 来宾配置 1 vCPU 和 96 MiB RAM，禁用虚拟网卡，独立启动一个非 root Cognitive OS 运行时。宿主通过串口同时触发两台来宾的负载。

| 来宾 | 启动耗时 | 持续负载 | 完成文件任务 | 错误 | P95 |
|---|---:|---:|---:|---:|---:|
| 1 | 8.10 秒 | 20.24 秒 | 40 | 0 | 152 ms |
| 2 | 6.78 秒 | 20.23 秒 | 40 | 0 | 148 ms |

运行前宿主可用内存为 989 MiB，测试最低 473 MiB。第二台来宾就绪时余量为 492 MiB，低于启动第三台的 544 MiB 门槛，因此本次确认 2 台同时通过。该结果对应当前后台负载和 TCG 来宾配置。QEMU 进程已清理。

原始数据保存在本地 `.validation/linux-capacity-20261107/` 和 `.validation/windows-capacity-20261107/`。Windows 来宾与测试脚本也保存在后者。
